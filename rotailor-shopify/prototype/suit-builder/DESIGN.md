## 1. ChatGPT で正確に作れなかった理由

| 起きたこと | 技術的な原因 |
| --- | --- |
| ボタン数・ラペルが指定どおりにならない | 画像生成 AI は「それらしい見た目」を確率的に作る仕組みで、「ボタンは 1 個」「剣先は上向き」といった構造の制約を保証できない。学習データで多い形（2 ボタン・ノッチ）に引き寄せられる |
| 変えたくない部分まで変わる | 「編集」も実際には画像全体を作り直している。マネキンの位置・シルエット・生地の色まで毎回わずかにずれる |
| ベストとジャケットの重なりが不自然 | 前後関係（どちらが上に重なるか）を理解して描いているわけではない |
| 大量に作っても使い回せない | 1 枚ごとに座標がずれるため、部品の差し替えや色替えの素材として位置が合わない |

**結論**：画像生成 AI に任せてよいのは「雰囲気のある土台写真を 1 枚作る」ところまで。
形（ボタン数・ラペル・重なり）は、**数値で決めてプログラムが描く**必要がある。

| 工程 | 担当 |
| --- | --- |
| マネキン・胴・袖・パンツの写真（土台） | 画像生成 AI（1 回だけ）。または実写撮影 |
| 部位の色分け（どこがスーツ／シャツ／ネクタイか） | 色分けした写真＋スクリプトでマスク化（`tools/build-suit-photos.py`） |
| 前身頃を消して土台を作る | スクリプト（`tools/build-front-base.py`） |
| ラペル・ボタン・前端・ベスト・V ゾーン | **プログラムで描画**（`builder.js`）。仕様は座標データ |
| 生地・シャツ・ネクタイの色柄 | プログラム（陰影を残したまま塗り替え：`theme/assets/suit-photo.js`） |

## 2. 実装方式の比較と選定

評価：◎ とても良い ○ 良い △ 課題あり × 不向き

| | A 透過 PNG の重ね合わせ | B SVG パーツ | **C 写真マスク＋形はコードで描画（採用）** | D 3D（CLO3D 等で作って書き出し／WebGL） |
| --- | --- | --- | --- | --- |
| 1. 構造の正確さ | △ 素材が正確なら○。素材を AI で作ると×（今回の失敗） | ◎ | ◎ 形は座標データで決まる | ◎ |
| 2. 写真らしさ | ◎ | × イラストになる | ○ 胴・袖・パンツは写真。前身頃はやや平面的 | ◎ |
| 3. 色・柄の変更 | △ パーツごとに陰影の整合が必要 | ○ | ◎ 写真の陰影を残して塗り替え | ◎ |
| 4. スマホでの動作 | ◎ | ◎ | ◎ 1 回の描画は数十ミリ秒 | △ 端末により重い |
| 5. 初期コスト | △ 正確な素材を撮影・制作する必要 | ○ | ○ 土台写真 1 枚＋コード | × 3D モデル制作（外注なら数十万円規模の見込み） |
| 6. 仕様追加の拡張性 | △ 組み合わせごとに素材が増える | ◎ | ◎ 形のデータを足すだけ | ◎ |
| 7. 素材の管理 | × 組み合わせ爆発 | ◎ | ◎ 写真 1 枚＋数値 | △ 3D データの管理 |
| 8. 運用費 | 0 円 | 0 円 | 0 円 | 0 円（ソフトの月額は別） |

**採用：方式 C**。理由：

- 構造の正確さが最優先（「見た目が綺麗でもボタン数が違えば失敗」）。C は形を数値で決めるので必ず仕様どおりになる
- 写真らしさは、面積の大きい胴・袖・パンツを写真のまま使うことで確保できる
- 運用費 0 円、素材は写真 1 枚。仕様を増やしても画像を作り直す必要がない

**将来の選択肢**：前身頃まで完全に写真品質にしたくなったら、方式 D（3D で作ったスーツを、同じカメラ位置で部品ごとに書き出し、C と同じ仕組みで重ねる）が本命。高級オーダーのシミュレーターの多くはこの作り方。費用がかかるため、まず C で反応を見てから判断する。

## 3. 素材・レイヤー設計

### 3.1 素材一覧（フェーズ1）

| ファイル | 内容 | 作り方 |
| --- | --- | --- |
| `front-base.jpg` | 前身頃を取り除いた土台写真（768×1152）。首元のシャツ襟・ネクタイの結び目だけ写真を残す | `tools/build-front-base.py`（元はシングル2ボタン・ノッチの色分け写真 01 番） |
| `front-base-mask.png` | 部位マスク。R＝スーツ／G＝ネクタイ／B＝シャツ | 同上 |
| `theme/assets/suit-builder.js` | 仕様 → 座標 → 描画（フェーズ4で本番に移動） | 手書き |
| `theme/assets/suit-photo.js` | 塗り替え（`compose`）と柄のタイル（`patternTexture`）。本番のシミュレーターと共通 | 既存 |

### 3.2 描画の順番（下から上へ）

```
1. 土台写真（front-base）を選んだ生地に塗り替え     … 胴・袖・パンツ・ポケット
2. V ゾーン（返り線の内側だけ）
   2a. シャツ（両端を暗く）
   2b. ネクタイの大剣（結び目の下から広がる台形）
   2c. ベスト（あり の時）… ベストの V・前端・ボタン 6 個。ジャケットの V から見える分だけ
3. ラペルの落ち影（胸と V ゾーンへ）
4. カッタウェイ（裾の開き）から見えるパンツ → 下前の前端 → 上前の前端と影
5. 上襟 → ラペル（右前 → 左前。左前＝着用者の右前が上に重なる）→ ノッチの切れ込み
6. 胸ポケット
7. フロントボタン（留めないボタンの横には上前のボタンホール）
```

前後関係は実物の仕立てに合わせています：
- 紳士服は**着用者の右前（画像の左）が上**に重なる。ボタンは下前の中心線上に付き、上前の前端は中心線より約 2cm 外（画像の右）に来る
- ボタンを留めると、ベストは**ジャケットの V の内側にしか見えない**（V の多角形で切り抜いている）
- 前身頃の重なりは**一番下のボタンの少し下まで**。そこから下はカッタウェイで開き、パンツが見える

### 3.3 仕様データ（座標は 768×1152 の写真上のピクセル。約 4.9px/cm）

```js
CLOSURES = {
  sb1: { type: 'single', overlap: 9,  breakY: 384, buttons: [{ dx: 0, y: 404, fastened: true }] },
  sb2: { type: 'single', overlap: 9,  breakY: 352, buttons: [{ dx: 0, y: 373, fastened: true }, { dx: 0, y: 440 }] },
  sb3: { type: 'single', overlap: 9,  breakY: 356, buttons: [{ dx: 0, y: 326, rolled: true }, { dx: 0, y: 374, fastened: true }, { dx: 0, y: 434 }] },
  db4: { type: 'double', overlap: 40, breakY: 352, drop: 44, buttons: [±25 × 2 段（上段の右を留める）] },
  db6: { type: 'double', overlap: 40, breakY: 300, drop: 80, buttons: [上段 ±60（飾り）, 中段 ±25（右を留める）, 下段 ±25] }
}
LAPELS = {
  notch: { tip, gorge, collarTip, belly, notchOpen: true }, // 上襟とラペルの間に切れ込み
  peak:  { tip（上向きの剣先）, gorge, collarTip（剣先の下に隠れる）, belly },
  shawl: { shawl: true, neck, belly }                       // 上襟とラペルが一続き
}
```

- `overlap`：上前の前端が中心線から外へ出る量。シングル約 2cm、ダブル約 8cm
- `breakY`：返り止まり（V の底）。ダブルも中心付近で、そこから前端が `drop` だけ斜めに下りて外側の列の外で垂直になる（ダブル 6 ボタンの参考写真で確認）
- `rolled`：3 ボタン段返りの一番上。ボタンはラペルの裏に隠れ、ボタンホールだけがラペルの返りに斜めに見える
- ラペルは画像左側だけ定義し、中心線 x=384 で反転して右側を作る。返り止まりが浅い（ダブル 6 ボタン）ときは外側の線の膨らみも上へ縮める
- 組み合わせの決まり（`normalize`）：ダブル → ピーク、ショール → シングル 1 ボタン

### 3.4 色変更の仕組み

- 写真部分：写真の明るさを「陰影」として取り出し、選んだ生地のタイルに掛ける（陰影の中央値＝生地の色そのまま）
- 描画部分：同じタイルを `createPattern` で塗り、陰影はグラデーションの乗算で付ける
- ジャケット・ベスト・パンツは同じ生地タイルを使用。別々の色にする場合は、ベスト用・パンツ用のタイルを渡せるよう `render()` の引数を分ければ対応できる（パンツはマスクの分割が必要。後述）

### 3.5 ファイル命名規則（フェーズ3以降）

| 種類 | 名前 | 例 |
| --- | --- | --- |
| 土台写真 | `base-<向き>.jpg` ／ `base-<向き>-mask.png` | `base-front.jpg`、`base-back.jpg` |
| 形データ | `builder.js` 内の `CLOSURES` / `LAPELS` / `VESTS` のキー | `CLOSURES['sb3-roll']`、`LAPELS.shawl` |
| アップ用の土台 | `detail-<部位>.jpg` | `detail-pocket.jpg`、`detail-hem.jpg` |

### 3.6 仕様の依存関係

- ボタン数 → 返り止まりの高さ → V の深さ・ラペルの長さ・重なりの終わり
- ダブル → 上前の前端が中心線から大きく外へ。ボタンは 2 列。ラペルはピーク固定
- 3 ボタン段返り → 返り止まりは 2 番目のボタン。1 番目のボタンはラペルの裏に半分隠れる
- ショール → 上襟とラペルが一続き（ゴージ・ノッチなし）。外側の線が丸く首まで続く
- ベスト → V の内側だけ。ダブルの場合も同じ（V が浅いので見える量が減る）

## 4. 精度の検証（フェーズ1）

`verification/` に、同じ土台・同じ構図で描いた結果を並べています。

| 確認項目 | 結果 |
| --- | --- |
| ボタン数 | ◎ 2 ボタン＝2 個（上を留め、下は留めない）、1 ボタン＝1 個。数は仕様データから描くので必ず一致 |
| ラペルの形 | ○ ノッチは上襟との切れ込み、ピークは上向きの剣先で区別できる（`grid-a.jpg`） |
| パーツの重なり | ○ ベストのボタンは V の内側だけに見え、ジャケットの返り止まりより下には出ない（`grid-b.jpg`） |
| 色変更時の陰影 | ○ 濃色は自然。ライトグレーなど淡い色では、描いたラペルが胴より少し暗く見える（`grid-c.jpg`） |
| 切り替え時の位置ズレ | ◎ 土台写真は 1 枚なので、マネキン・胴・袖・パンツは 1 ピクセルも動かない |

### フェーズ2の検証

| 確認項目 | 結果 |
| --- | --- |
| 前合わせ 5 種 | ◎ 1 ボタン／2 ボタン／3 ボタン段返り（上のボタンは隠れ、ボタンホールのみ）／ダブル 4（2×2）／ダブル 6（上段が外側の 6×2）（`phase2-closures.jpg`） |
| ラペル 3 種 | ◎ ノッチ／ピーク／ショール（丸く首まで一続き） |
| ベストとの重なり | ◎ 全前合わせで V の内側だけに見える。ダブル 6 ボタンは V が浅いため見える量が少ない（`phase2-with-vest.jpg`） |
| 色柄 | ○ 淡いグレーでもラペルが暗くならない。ストライプはラペルの向きに沿う（`phase2-cloth.jpg`） |

### 分かっている課題

1. 描いた前身頃（ラペルまわり）は写真より平面的。ステッチ、ラペルの返りの丸み、生地の厚みの表現を足すと改善する
2. ~~淡い色の生地でラペルが暗く見える~~ → フェーズ2で解消（生地の明るさに応じて陰影を弱める）
3. ~~ストライプがラペル上でも垂直のまま~~ → フェーズ2で解消（ラペルの向きに柄を回転）
4. 土台写真の胸元は、元のラペルを消して周りから補間したため、陰影がやや単調
5. ダブルでもカッタウェイのない裾は、土台写真（シングル）の裾の形のまま。前端の線だけで表している
